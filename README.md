# Сервис сокращения ссылок 
#### Основные задачи:
1. **Создание коротких ссылок.** Система должна принимать длинный URL и преобразовывать его в короткую ссылку. Пример: при передаче ссылки https://www.baeldung.com/java-9-http-client вы должны получить короткий вариант clck.ru/3DZHeG.
2. **Уникальные ссылки для каждого пользователя.** Если один и тот же ресурс сокращают разные пользователи, они должны получать уникальные сокращенные ссылки.
3. **Лимит переходов.** Пользователь может задать максимальное количество переходов по ссылке. Как только этот лимит исчерпан, ссылка должна стать недоступной.
4. **Ограничение времени жизни ссылки.** Время жизни ссылки должно задаваться системой и ограничиваться определенным сроком (например, сутки). После истечения этого срока ссылка должна автоматически удаляться.
5. **Уведомление пользователя.** Пользователь должен получать уведомление, если лимит переходов исчерпан или время жизни ссылки истекло.
6. **Идентификация пользователя по UUID.** Каждый пользователь идентифицируется без авторизации с помощью UUID, который генерируется при первом запросе на создание короткой ссылки. Этот UUID используется для отслеживания всех действий пользователя с его ссылками.

#### Процесс создания
По скольку нельзя было использовать архитектуру клиент-сервер, разрабатывалось обычное консольное приложение.
Для разделения пользователей в приложении пришлось применить уникальные логины, которые генерируются при первом запросе на создание ссылки.
Они связаны с UUID, гарантируется уникальность каждого пользователя. Для работы со ссылками пользователя используется UUID.     
В приложении слой презентации реализован через класс Controller, он принимает массив строк(уже разделенную команду на слова), 
обрабатывает команды, выдает сообщения пользователю или переход по ссылке на ресурс. 
В нем вложенный класс Setting, который хранить/загружает настройки, время жизни ссылок.    
Бизнес логика класс Service, хранит в Map структуре пользовательские ссылки и проводит операции с ними, 
вложенным классом Generator генерируются короткие ссылки, UUID, логины.    
В слое repository класс Storage сохраняет в файлы и загружает из файлов пользовательские данные. 
Запись в формат json и обратно через библиотеку com.fasterxml.jackson.core:jackson-databind:2.22.4     
В файле help.txt в resources описаны команды пользователя.      
Модели данных хранятся в слое domain.    
- LInk содержит длинную ссылку, время создания короткой, лимит переходов.
- UserLink содержит ассоциативный массив, ключ: короткая ссылка, значение: Link 

#### Описание работы
Сервис принимает ссылки типа https:// и генерирует короткую ссылку link/ на ресурс,
так же осуществляется переход по короткой ссылки на запрашиваемый ресурс, учитывается заданное кол-во переходов, заданное при создании короткой ссылки пользователем.     
Время жизни ссылки ограниченно, оно устанавливается администратором. Дефолтное значение 1 час.
Ссылки удаляются по истечении лимитов переходов или времени жизни ссылки.    
Пользователь при запросе получит соответствующее уведомление.

Создавая первый раз ссылку пользователь получает уникальный логин. С этим логином пользователь может проводить различные операции:
- сгенерировать новую ссылку на другой ресурс.
- заменить короткую ссылку другой, создав новую на тот же ресурс.
- перейти по короткой ссылке.
- изменить лимит переходов по короткой ссылке.
- просмотреть все свои ссылки с оставшимся лимитом переходов или статусом(если ссылки удалены). 
- удалить короткую ссылку. 
- удалить свой аккаунт со всеми своими ссылками.

Все действия со ссылками пользователем описаны в справке помощь, вызов - П. см. файл help.txt в resources

Администратор может корректировать время жизни ссылок, команда:
admin time новое значение      
Минимальное время жизни 5 минут, устанавливается в сек., 300.
Так же корректировка возможна в сохраняемом файле setting.txt, пример:     
#Setting     
#Wed Nov 11 23:00:17 IRKT 2026      
timeActive=300000     
Установка в файле 300000 миллисекунд = 5 мин.

Все данные, пользователи их ссылки, в формате json сохраняются при выходе из программы в папке database, 
- файл User.json - пользователи (логин = UUID),
- файл UserLink.json - их ссылки (UUID, ссылки) 

При запуске приложения, данные пользователей, их ссылок, времени жизни из файлов загружаются в программу.
